1什么是 Git？为什么需要它？

你写了一个 HTML 文件，改了又改，最后搞不清楚哪个版本是最新版。手动复制备份？guide_v1.html、guide_v2_final.html、guide_v2_final_really_final.html……是不是很熟悉？

Git 就是一个自动帮你记录每次修改的"时光机"。它不是备份软件，而是版本控制系统——每次你改完文件，告诉 Git "记一下"，它就把当前所有文件的状态拍一张"快照"存起来。以后随时可以回到任何一个历史版本。

一句话理解 Git Git = 一本能自动记录每次改动的账本。你只管改文件，Git 负责记住"谁在什么时候改了什么"。
普通文件夹
一堆文件，改了就覆盖
-->
git init
给文件夹开一本账本
-->
Git 仓库
每次改动都有记录

2Git 三大区域：工作区 / 暂存区 / 仓库

理解 Git 最关键的一步，就是搞清楚它的三个区域。文件从"改了"到"正式记录"，要经过三个地方：

Git 三大区域：文件的变化之旅
为什么要三个区域？ 如果只有"工作区"和"仓库"，你每改一个文件就得立刻 commit，太烦了。有了暂存区，你可以先改 5 个文件，add 进暂存区，最后一次 commit 把它们打包成一条记录。灵活又干净。

3git init：给文件夹开一本账本

你 Mac 上有一个普通文件夹，里面放着 HTML 文件。GitHub 不认识它，也没法推送。需要先把它变成 Git 仓库。

进入文件夹并初始化
cd ~/sama5/sama5d27-docker-guide
git init
  • cd ~/sama5/sama5d27-docker-guide — 进入你要管理的文件夹
  • git init — 给这个文件夹"开一本账本"。执行后，Git 会在文件夹里创建一个隐藏的 .git 目录，用来存储所有版本记录。从这一刻起，这个文件夹就不再是普通文件夹，而是Git 仓库了。
git init 只需要做一次 初始化之后，这个文件夹永远是 Git 仓库，以后不用再 init 了。

4git add：标记变化（含 -A 详解）

你改了文件，但 Git 还不知道。需要用 git add 告诉 Git："这些文件变了，待会 commit 时记上。"

标记所有变化
git add -A
  • git add -A — -A 是 --all 的缩写，意思是"把所有变化都标记"。Git 会自动扫描整个仓库目录，发现哪些文件变了（不管是改了、加了还是删了），全部标记上。

-A 到底抓了哪些变化？具体例子

假设你的仓库目录里有三个文件，你做了三个操作：

操作文件变化类型
改了 HTML 里的内容guide.html修改 (Modified)
新建了一个文件notes.txt新增 (Added)
删掉了旧文件old-version.html删除 (Deleted)

不加 -A 的情况：你得手动一条条加：

逐个标记（麻烦）
git add guide.html
git add notes.txt
git rm old-version.html

三个操作，三条命令，漏一条就少记录一个变化。

加 -A 的情况：一条命令，三种变化全部自动标记：

一条搞定（推荐）
git add -A
一句话理解 -A "别让我一条条指定了，你自己扫一遍，所有变的都给我标记上。" 省事，不遗漏。
add 之后文件没有正式记录 git add 只是把文件从"工作区"搬到"暂存区"，打了个标记。Git 还没有正式记录这次变化。需要 git commit 才会真正拍快照。

5git commit：拍一张快照

git add 只是标记了"哪些文件变了"，git commit 才是正式把这些变化"拍一张快照"记录下来。

提交快照
git commit -m "完善 nohup 命令拆解、重定向讲解"
  • git commit — 把暂存区里标记的文件"拍一张快照"存到本地仓库
  • -m "说明" — -m 是 message 的缩写，后面的引号里写这次改了什么。这条说明会永久记录在 Git 历史里，方便以后查看。

每次 commit 会生成什么？

每次 commit，Git 会生成 5 样东西：

项目说明实际例子
快照 IDGit 根据内容算出的唯一编号e15612d
时间提交的时间戳2026-08-15 22:05:34
作者谁提交的alan <yucheng_studio@163.com>
说明你写的 -m 内容"完善 nohup 命令拆解"
文件变化哪些文件改了多少行index.html +134 -1

快照 ID 是怎么算出来的？

快照 ID（如 e15612d）是 Git 根据文件内容、时间、作者等信息用哈希算法算出来的。内容只要有一个字不一样，ID 就完全不同。所以它是全球唯一的，不会重复。

完整 ID 是 40 位十六进制：e15612d2e502bf8a72b437d770b84e6deb44e79a。日常使用只看前 7 位 e15612d，足够区分。

6git remote：关联 GitHub 仓库

本地仓库建好了，但 GitHub 上还不知道有这个仓库。需要用 git remote add 把本地仓库和 GitHub 仓库关联起来。

关联远程仓库（只需做一次）
git remote add origin git@github.com:yuchengstudio/embedded-linux-lab.git
  • git remote add — 添加一个远程仓库地址
  • origin — 给这个远程仓库起的别名。以后写 origin 就代表这个地址，不用每次写完整 URL。
  • git@github.com:... — GitHub 仓库的 SSH 地址。注意是 git@ 开头，不是 https:// 开头。
HTTPS vs SSH 地址

GitHub 仓库有两种地址：

  • HTTPS：https://github.com/用户名/仓库名.git — 每次推送要输用户名和 Token
  • SSH：git@github.com:用户名/仓库名.git — 用密钥自动认证，不用输密码

如果你用 gh auth login 登录时选了 SSH，远程地址就必须用 SSH 格式，否则推不了。

如果配错了，改成 SSH 格式
git remote set-url origin git@github.com:yuchengstudio/embedded-linux-lab.git

8SSH 认证全过程：6 步签名流程

公钥私钥搞懂了，接下来看每次 git push 时，Mac 和 GitHub 之间到底发生了什么。这个过程叫 Challenge-Response（挑战-响应）认证。

SSH 签名认证：6 步流程（用具体数据演示）
如果有人冒充你呢？

1. GitHub 发挑战给攻击者

2. 攻击者没有你的私钥，无法算出正确的签名

3. 随便编一个签名发过去，GitHub 用公钥验证 → 对不上 → 拒绝推送

就算攻击者偷到了你上次的签名也没用，下次挑战是新的随机数，旧签名对不上。

9git push：推送到 GitHub

本地 commit 拍完快照后，需要用 git push 把它推送到 GitHub。

推送到 GitHub
git push -u origin main
  • git push — 把本地 commit 推送到远程仓库
  • -u — 记住"以后 push 默认推到 origin 的 main"，下次只打 git push 就行
  • origin — 远程仓库的别名（你之前 git remote add 时设的）
  • main — 你本地那条时间线（分支）的名字

整句翻译：把本地 main 分支上的所有 commit，推到 origin（GitHub）的 main 分支上去。

-u 只需要第一次加 第一次推送加 -u 后，Git 记住了默认目标。以后推送只需要 git push，不用再写完整命令。

深入：推送完整流程详解（7 层拆解）

上面的 4 步是简化版。下面把每一步拆开，用你实际的推送数据（bc1af84..e15612d）逐层讲透，从文件位置到 SSH 认证到终端输出，一层一层来。

推送完整流程：7 层总览

① 两个文件的位置

你的 HTML 有两份：主文件在 ~/WorkBuddy/.../sama5d27-docker-guide.html（我帮你改的就是这个），仓库副本在 ~/sama5/sama5d27-docker-guide/（用来推 GitHub 的）。Git 只认自己仓库目录里的文件，所以第一步必须 cp 把主文件搬过去覆盖旧的。搬完之后 Git 还认不出来你改了什么——它只是在硬盘上多了一个新版的文件。

② git add -A：标记所有变化

文件从"工作区"进入"暂存区"。Git 扫一遍仓库目录，发现哪些文件变了（修改、新增、删除三种），全部打上标记。-A = --all，意思是"别让我一条条指定了，你自己扫一遍，所有变的都给我标记上"。

add 不改文件内容，只是给 Git 打个标记："这个文件变了，待会 commit 时记上"。打完标记后 Git 知道你改了，但还没有正式记录。

③ git commit -m "说明"：拍一张快照

Git 做三件事：① 把暂存区里标记的文件"拍一张快照"存到本地仓库 ② 生成唯一 ID（如 e15612d）③ 写上你指定的说明文字。

快照 ID 是 Git 根据文件内容用哈希算法算出来的——内容变一个字，ID 就完全不同。旧快照不删，形成历史链：e1d6798 → 25831de → 9f1ac95 → e15612d。此时本地有新版了，但 GitHub 上还没有。

④ git push -u origin main：推送到 GitHub

分三个子步骤：① 把 commit 打包压缩成 Git 对象 ② 通过 SSH 加密通道传输 ③ GitHub 收到后写入远程仓库。

origin 是远程仓库地址的别名 = git@github.com:yuchengstudio/embedded-linux-lab.git。main 是你本地那条时间线的名字。-u 表示记住"以后 push 默认推到 origin 的 main"，下次只打 git push 就行。

⑤ SSH 认证：公钥私钥验证身份

每次 push，GitHub 不是直接接收文件，而是先验证你的身份。过程：① GitHub 生成一段随机字符串（挑战）发给你的 Mac ② Mac 读取私钥 ~/.ssh/id_ed25519，对挑战字符串做签名运算 ③ 只把签名结果发给 GitHub，私钥本身不出 Mac ④ GitHub 用你之前上传的公钥验证签名，通过 = 确认是你。

用印章打比方：GitHub 每次给你发一张白纸（随机挑战），你用私人印章盖一下（私钥签名）发回去，GitHub 用验印章的模具（公钥）对一下印记，对上了就确认是你。印章全程在你手里，别人偷不到。

⑥ 终端输出逐行解读

push 时终端打印的每一行都代表一个步骤：

  • Enumerating objects: 14 — 数变化，发现有 14 个 Git 对象要传
  • Delta compression using up to 8 threads — 差分压缩，8 个 CPU 核并行压缩
  • Resolving deltas: 100% (7/7) — GitHub 收到后还原 7 个差异块，拼出完整新文件

  • main -> main — 从本地 main 分支推到 GitHub 的 main 分支

⑦ 首次准备（只做一次）

git init（给文件夹开账本）→ git remote add origin（关联 GitHub 仓库地址）→ gh auth login -w（SSH 登录，上传公钥）。这三步已经做完了，以后每次改完 HTML 只需要走 ① 到 ④ 四步就行。

Git 传文件不是整个传，而是只传"改了哪些行"（叫 delta，差异）。具体到你的例子：

  2. 传输：只传这 7 个差异块过去（27KB），不传整个文件
  3. GitHub 收到后：手里有旧版，收到 7 个差异块后，逐个"拼"到旧版上 → 还原出 e15612d（新版）

13常见问题 FAQ

Q: push 被拒绝，提示 "Updates were rejected because the remote contains work"

原因是 GitHub 仓库上已有内容，而你本地没有那些内容。Git 不让你直接覆盖。

解决：先拉取再推送：

git pull origin main --rebase
git push -u origin main

如果报 CONFLICT（冲突），说明本地和远程改了同一个文件，需要手动解决冲突后再 commit 和 push。

Q: push 报错 "Permission denied (publickey)"

原因是 GitHub 没有你的公钥，或者远程地址配成了 HTTPS 但你登录选了 SSH。

解决：

  1. 检查远程地址格式：git remote -v
  2. 如果是 HTTPS，改成 SSH：git remote set-url origin git@github.com:用户名/仓库名.git
  3. 确认公钥已上传：gh auth status 或去 GitHub Settings - SSH keys 查看
Q: git add 和 git commit 有什么区别？

git add：把文件从"工作区"搬到"暂存区"，只是打个标记说"这个文件变了"。Git 还没有正式记录。

git commit：把暂存区里标记的文件正式"拍一张快照"存到本地仓库。这才是正式记录。

比喻：add = 把商品放进购物车；commit = 结账下单。你可以 add 很多次，最后一次性 commit。

Q: git push -u 里的 -u 是什么意思？

-u 是 --set-upstream 的缩写。它的作用是记住"以后 push 默认推到 origin 的 main 分支"。

第一次推送加 -u 后，以后只需要打 git push，不用再写完整的 git push origin main。

Q: 什么是 SSH 隧道？

SSH 隧道就是你 Mac 和 GitHub 之间的一条加密管道。数据进入管道前被"锁进密码箱"变成乱码，到达 GitHub 后才"解锁"还原。沿途经过的路由器、运营商，看到的只是一堆乱码。

不加密 = 明信片，谁都能偷看；SSH 隧道 = 密码箱，只有两端能读懂。

Q: 私钥丢了怎么办？

私钥丢了 = 别人可能捡到 = 别人能冒充你推送代码。立即：

  1. 去 GitHub Settings - SSH keys 删掉对应的公钥
  2. 本地重新生成：ssh-keygen -t ed25519 -C "你的邮箱"
  3. 重新上传公钥：gh auth login -w
Q: commit ID 为什么是乱码？

commit ID 是 Git 根据文件内容、时间、作者等信息用 SHA-1 哈希算法算出来的。内容只要有一个字不一样，ID 就完全不同。所以它是全球唯一的，不会重复。

完整 ID 是 40 位（如 e15612d2e502bf8a72b437d770b84e6deb44e79a），日常只看前 7 位（e15612d），足够区分。
